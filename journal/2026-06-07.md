## ~1:27 — "autograd" and "backprop" — words I didn't know yet

Karpathy threw out "autograd engine" and "backpropagation" in the intro and I had no
idea what they meant. Got them explained:

- **Gradient** = a slope. "If I nudge this input up a hair, how much does the final
  answer move, and which way?" Example that made it click: `L = a*b`, a=2 b=3 → L=6.
  Nudge a to 2.01 and L goes to 6.03 → moved 0.03 for a 0.01 nudge → slope = 3. And
  that 3 is just b. So the gradient is *sensitivity*: how much the output cares about
  this knob.
- **Why care:** training = turning thousands of knobs (weights) to shrink the error.
  The gradient on each knob says which way to turn it. No gradients, no learning.
- **Backpropagation** = the efficient way to get the gradient for *every* knob in a
  long chain of operations. Compute the answer left-to-right (forward), then walk
  backwards right-to-left multiplying the local slopes (that's the chain rule). Do the
  backward pass *once* and every knob's gradient falls out.
- **Autograd engine** = "automatic gradient" — software that records every operation
  into a graph as you build it, then runs backprop over that graph automatically so I
  never do calculus by hand. **micrograd IS that engine** — the thing I'm building.
  The `Value` object he mentioned is the part that records the operations.

Takeaway I'm holding onto: I don't need to *get* this yet. The whole video makes it
concrete by building it. The fog should start lifting at the `Value` object.
