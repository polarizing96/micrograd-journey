## ~1:27 — "autograd" and "backprop" — words I didn't know yet

Karpathy threw out "autograd engine" and "backpropagation" in the intro and I had no
idea what they meant. Got them explained:

- **Gradient** = a slope. "If I nudge this input up a hair, how much does the final
  answer move, and which way?" Example that made it click: `L = a*b`, a=2 b=3 → L=6.
  Nudge a to 2.01 and L goes to 6.03 → moved 0.03 for a 0.01 nudge → slope = 3. And
  that 3 is just b. So the gradient is *sensitivity*: how much the output cares about
  this knob.
- **Why care:** training = turning thousands of knobs (weights) to shrink the error.
  The gradient on each knob says which way to turn it. No gradients, no learning.
- **Backpropagation** = the efficient way to get the gradient for *every* knob in a
  long chain of operations. Compute the answer left-to-right (forward), then walk
  backwards right-to-left multiplying the local slopes (that's the chain rule). Do the
  backward pass *once* and every knob's gradient falls out.
- **Autograd engine** = "automatic gradient" — software that records every operation
  into a graph as you build it, then runs backprop over that graph automatically so I
  never do calculus by hand. **micrograd IS that engine** — the thing I'm building.
  The `Value` object he mentioned is the part that records the operations.

Takeaway I'm holding onto: I don't need to *get* this yet. The whole video makes it
concrete by building it. The fog should start lifting at the `Value` object.

## The words didn't stick — needed to SEE it (visual learner)

Reading the explanation didn't do it. The calculus felt abstract. So we built an
interactive page: `viz/01-gradient-is-a-slope.html` (open in browser, drag sliders).

What it shows on y = x²:
- Drag **x** → a red line (the slope = gradient) tilts. Steep-up at x=2 (~+4),
  steep-down at x=-2 (~-4), flat at x=0 (0). Sign = direction, size = steepness.
- A green triangle = the "nudge": step right by h (run), curve steps up by Δy (rise).
  Slope = rise/run.
- **The aha I'm chasing:** drag **h** toward 0 → the green nudge-line swings onto the
  red line, and Δy/h settles onto the gradient number. THAT is what a derivative is —
  the slope of the nudge once the nudge shrinks to nearly nothing. Not a scary formula,
  just the wiggle ratio after you stop shrinking.

Connection I want to remember: that red number = the `.grad` every `Value` will carry.
Backprop = compute this slope for every knob at once.

## The nudge slider missed the point — what I actually needed was the "so what"

I changed the nudge slider and went "...so what?" Fair. The nudge thing only shows what
a derivative *technically is*; it didn't tell me why I should care.

The real point, said plainly: **the slope tells you which way to turn a knob to make a
number go down.** That's the whole reason gradients exist.

Built a second viz to show it: `viz/02-why-slopes-matter.html`.
- A valley curve = the "error" (lower = better). A red ball = my knob setting.
- Press "step downhill" → ball rolls toward the bottom, error number drops.
- Green arrow = the slope. Ball always steps the OPPOSITE way the arrow points.
- At the bottom the slope → 0 and it stops: no more downhill, knob is "trained."

That IS training: slope = downhill direction → step opposite it → error falls → repeat.
A neural net = this with thousands of knobs. Backprop = compute every knob's slope at
once so they all roll downhill together.

## Warmer/colder finally cracked it 🎉

The "warmer/colder hide-and-seek" analogy is what landed:
- where I'm standing = the knob (weight)
- distance from the toy = the error (want it ~0)
- small test-step to hear "warmer/colder" = the nudge (measures the slope/direction)
- walking toward "warmer" repeatedly = rolling downhill = training
- standing on the toy, every way is colder = the bottom = done

Key fix to my earlier confusion: **nudge and step are two different small numbers.**
- nudge = throwaway test-poke to MEASURE which way is downhill
- step = how far I actually walk = the **learning rate**

## My question: why not just take huge steps? (is it binary search?)

Answer: warmer/colder tells me the *direction*, not the *distance*. So:
- huge step → leap past the toy, land on the far side (colder), turn around, overshoot
  again → bounce forever, or fly off and the error EXPLODES.
- tiny step → gets there but painfully slow.
- sweet spot in between → glides in. Tuning this is a real ML job.

NOT binary search: binary search has a *map* (known sorted range to halve). Here I'm in
*fog* — I can only feel the slope under my feet, can't see where the bottom is. It's
"walk downhill blindfolded," not "halve a known range." (Neat bit: the slope's *size*
gives a distance hint — steeper = take bigger step, flattens near bottom = ease in. That's
why the ball slowed down approaching the bottom in demo 2.)

Built `viz/03-step-size-learning-rate.html` — a step-size slider with presets (tiny /
good / perfect / bouncy / explode). Cranking it up and watching the ball overshoot and
then explode is exactly my "why not huge steps" question made visible.

## Step made sense but nudge still didn't — isolating it

Got the step-size demo but the nudge was still murky. The missing sentence: in the
rolling-ball demo the slope arrow just *appeared* — but the computer doesn't magically
know the slope, **it pokes the knob to find out. That poke IS the nudge.** The nudge's
only job = MEASURE the slope.

With numbers: knob 3.00→3.01 (moved 0.01), output 9.00→9.06 (moved 0.06),
slope = 0.06 ÷ 0.01 = 6. Means "push knob up 1, output rises ~6."

The analogy that should nail it: a **speedometer**. "60 mph" is a slope = miles per hour.
The car measures it by watching distance over a tiny slice of time and dividing. Speed is
a nudge in time; a gradient is a nudge in a knob. Same move.

Built `viz/04-the-nudge.html`: a knob + a Poke button. Poke → knob moves a hair, output
reacts, slope = output-move ÷ knob-move shown explicitly. Poke at knob=2 (steep), knob=0
(flat, ~0), knob=-2 (negative) to feel that the slope depends where you are.

Pipeline straight: nudge to MEASURE the slope → step downhill to USE it. [pending: did
the poke demo land?]

## 🎉 IT CLICKED — I figured out the nudge-vs-step distinction myself

I asked: "is step actually going in that direction, so nudge is like testing?" — and
yes, that's exactly right. That's the whole thing:

- **Nudge = testing.** A tiny throwaway poke to sense which way is downhill + how steep.
  You don't keep it. (= glancing at the speedometer)
- **Step = the real move.** Now that the test told me the direction, I actually move the
  knob that way to lower the error. I keep this one. (= turning the wheel)

Each round: TEST which way (nudge) → GO that way for real (step) → repeat. Test → go.

Footnote for later: real micrograd doesn't literally poke every knob (too slow for
thousands) — it uses calculus (chain rule) to get the same slope instantly. The nudge is
just the right picture of WHAT that number means; the chain rule is the shortcut to it.

Foundation I now actually have:
- gradient = slope = which way downhill + how steep
- nudge = the test that measures it
- step = the real move that uses it (learning rate = how big)
- repeat → error falls → that's training
