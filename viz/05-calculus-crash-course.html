No calculus background assumed. Each idea is a couple minutes + a quick quiz to lock it in. Everything connects straight to the code you're about to write in value.py.

  1. Derivative = slope — you already get this (it's the nudge)

1 · recap Derivative = slope (decoding the symbols)

A derivative is just the slope you already understand: "if I nudge the input a tiny bit, how fast does the output change?" The scary part is only the notation. Decoder ring:

f(x) — the machine. Feed it x, get a number out.

f'(x) — "f prime" — the machine's slope rule. Feed it x, get the slope there.

dy/dx — reads "change in y per change in x." The d just means "a tiny change in." Same thing as the slope.

All three mean: the slope = the nudge ratio.

micrograd link: every Value stores .grad — that's just f' evaluated for that node: "how much does the final loss move if I nudge me?"

2 · the workhorse The power rule

For a knob raised to a power, f(x) = xn, the slope is:

📏 slope of xn = n · xn−1
Recipe: bring the exponent down to the front, then knock 1 off the exponent.
x² → 2·x¹ = 2x x³ → 3·x² x⁵ → 5·x⁴ x → 1·x⁰ = 1 (x is x¹, and anything⁰ = 1)

Sanity check: remember the algebra from before — poking x² gave 2x + h, and shrinking the poke to 0 left 2x. The power rule is just that result, memorized so you skip the poke.

3 · easy ones Constants & the sum rule

📏 A plain number has slope 0.  (slope of 7 is 0 — a flat line doesn't tilt)
📏 A multiplier rides along: slope of 3·x² = 3·(2x) = 6x
📏 Sum rule: the slope of a sum = the sum of the slopes. Do each piece separately.
slope of ( x² + x³ ) = 2x + 3x² slope of ( 5x² + 7 ) = 10x + 0 = 10x
micrograd link: this is the + node. When gradient flows back through a +, it passes straight through unchanged to each input (each input's local slope is 1). Addition just splits the gradient.

4 · careful here The product rule

When two things are multiplied, you can't just multiply their slopes. The rule:

📏 slope of (f · g) = f' · g + f · g'
"(slope of first × second) + (first × slope of second)"
slope of ( x · x² ): f = x → f' = 1 g = x² → g' = 2x = 1·x² + x·2x = x² + 2x² = 3x² ✓ (and x·x²=x³, whose slope is 3x²)
micrograd link: this is the * node — and here's the punchline you'll code: at out = a*b, the local slope toward a is just b, and toward b is just a. Each input's local slope is the other input. That's the product rule doing its job.

5 · THE big one The chain rule = backprop

Knobs in a network aren't wired straight to the output — they sit at the start of a chain. The chain rule tells you a buried knob's effect on the output. The idea is dead simple: slopes multiply along the chain.

Think of each step as an amplifier. Nudge x; it makes c move 3× as much; c makes out move 2× as much. So x moves out by 3 × 2 = 6×.

x→×3→ c→×2→ out overall slope of out w.r.t. x = 3 × 2 = 6
📏 Chain rule: if out = f(g(x)), then slope = f'(g(x)) · g'(x) = (outer slope) × (inner slope). Multiply the local slopes along the path.

cheat sheet The rulebook micrograd hard-codes

You don't derive these — you just look them up. micrograd writes one of these per operation, then snaps them together with the chain rule.

constant c  →  0
xn  →  n·xn−1
a + b  →  slope 1 to each (passes through)
a · b  →  slope b toward a, slope a toward b (the other one)
ex  →  ex  (its own slope — wild)
tanh(x)  →  1 − tanh(x)²
ReLU(x)  →  0 if x<0, else 1
